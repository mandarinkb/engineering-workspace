# ที่เคยพลาด และตัวกัน

อ่านก่อนเฟส 4 (implement) และอีกครั้งก่อนเฟส 7 (พิสูจน์) แต่ละข้อคือเหตุการณ์จริงในงานที่ใช้ skill นี้

| ที่พลาด | ตัวกัน |
|---|---|
| รายงานว่าแก้เสร็จทั้งที่สคริปต์ที่แก้ไฟล์ล้มด้วย syntax error ไม่ได้เขียนอะไรลงไฟล์ | หลังรันสคริปต์แก้ไฟล์ทุกครั้ง ตรวจผลบนดิสก์ (`ls`, `grep`, นับ) ก่อนบอกว่าเสร็จ เขียนสคริปต์เป็นไฟล์ ไม่ฝังในคำสั่ง shell ที่มี escape ซ้อน |
| งานเบื้องหลังจบด้วย exit 0 ทั้งที่ Go test ล้ม | exit code ของคำสั่งครอบไม่ใช่หลักฐาน อ่านผลทุกบรรทัด หาคำว่า FAIL, `×`, `build failed` |
| merge ที่ git ไม่เห็น conflict แต่พัง compile (ticket หนึ่งเปลี่ยน signature อีก ticket เขียน test ที่เรียกแบบเก่า; ticket หนึ่งแก้ฟังก์ชันให้คืน struct อีกตัวยังคืน `""`) | build + test หลัง merge ทุกครั้ง ก่อนเปิด subagent ตัวถัดไปที่ขึ้นกับมัน ticket ที่แก้ package เดียวกันขนานกัน ให้ระวังเป็นพิเศษ |
| `PUT` กลับด้วยค่าที่ `GET` ให้มา แล้วชื่อ workflow ของ Schedule จริงของผู้ใช้เปลี่ยนเงียบๆ (API คืนชื่อ type ไม่ใช่ชื่อที่ตั้ง) | ก่อนแก้ข้อมูลจริง เทียบสิ่งที่ API คืนกับสิ่งที่มันรับ และตรวจผลข้างเคียงหลังแก้ในระบบต้นทาง (Temporal) ไม่ใช่แค่ HTTP 200 |
| ตรวจ "หน้าอัปเดตเอง" แล้วขึ้น ✓ ทั้งที่งานจบใน 2 วินาที หน้าไม่เคยแสดงสถานะเริ่มต้น | ดู `testing.md` หัวข้อกันผ่านปลอม: ใช้งานที่ค้างนาน รอเห็นสถานะเริ่มต้นก่อน คำเตือนของสคริปต์แปลว่ายังไม่พิสูจน์ |
| บรรยายปุ่มของ UI ที่ไม่ได้กดว่าทำอะไร ราวกับยืนยันแล้ว | แยก "เห็นปุ่มนี้จริง" ออกจาก "ความหมายจากความรู้ทั่วไป" ในเอกสาร และบอกว่าไม่ได้กดปุ่มไหน |
| subagent หลายตัวรัน container พร้อมกัน Mini PC load 95 | ใส่กฎ "หนึ่ง container ต่อ subagent และรอเมื่อมี 3 ตัว" ใน prompt ตั้งแต่ต้น (`environment.md`) |
| usage limit เต็มกลางงาน subagent หยุดทั้งหมด | งานยังอยู่ใน worktree ใช้ `SendMessage` เรียกกลับทีละตัว แจ้งสถานะปัจจุบันของเครื่องเมื่อกลับมา |
| worktree ของ subagent ลบไม่ได้เพราะถูกล็อกโดย Claude Code | `git worktree unlock` แล้ว `git worktree remove` (ไม่ `--force`) ตรวจว่าไม่มีไฟล์ค้างและ branch ถูก merge ก่อน ไม่ใช้ `rm -rf` |
| ลบข้อมูลทดสอบด้วยเงื่อนไขกว้างเกินไป | ID ตรงตัวหรือ prefix ของตัวเอง คำสั่งฐานข้อมูลที่ปฏิเสธเมื่อจำนวนไม่ตรง หรือรายงานจำนวนที่เก็บไว้ ถ้ารายการที่คาดดูไม่ได้ (คำสั่ง list ล้ม) ใช้ผลนับก่อนและหลังเป็นหลักฐาน และบอกตามจริง |
| ตัดสินใจเรื่องที่ผู้ใช้ยังไม่ได้ตอบ (จำนวน replica) เพราะผู้ใช้สั่งให้ทำให้เสร็จ | เลือกทางที่เรียบง่ายและมีสวิตช์ปิด เขียนใน ticket ว่าเป็นการตัดสินใจของผู้ดำเนินการ ไม่ใช่ของเจ้าของระบบ พร้อมวิธีย้อน และบอกผู้ใช้ในรายงาน |
| ข้อความ "Request interrupted by user" โดยไม่มีข้อความตามมา | ทำเฉพาะงานที่ย้อนได้ในเครื่อง หยุดงานที่กระทบนอกเครื่อง (push, deploy) แล้วถามหนึ่งข้อ |
| บอกผู้ใช้ว่าติดตั้ง Playwright MCP แล้วใช้ได้ แต่ tool ไม่โหลดใน session เดิม | ค้นด้วย `ToolSearch` ก่อนใช้ ถ้าไม่เจอให้บอกตรงๆ แล้วใช้ไลบรารีแทน และบอกว่าต้องเริ่ม session ใหม่ถึงจะใช้ MCP |
| 20 request "ไม่มี session" ใน Bruno ล้ม ทั้งที่ API ถูกต้อง | cookie jar ของ Bruno CLI ดู `testing.md` เช็คด้วย `curl` ตรงๆ ก่อนสรุปว่าเป็นบั๊กของ API |
| รายงานว่า deploy แล้วทั้งที่ container ไม่ถูก recreate (ความต่างเป็นเอกสารล้วน image ไม่เปลี่ยน) | บอกผู้ใช้ตามจริงว่า build แล้วแต่ไม่มี restart เพราะไม่มีโค้ดเปลี่ยน |
| ค้าง branch ของงานบน Mini PC หลังผู้ใช้ merge แล้ว | เฟส 9: ตรวจว่าความต่างเป็นเอกสารล้วนแล้วสลับกลับ `main` |
| ตัวเลขที่รายงานมาจากความจำ (จำนวน test, จำนวน request) | อ่านจากผลที่พิมพ์ออกมาแล้วใส่ตัวเลขนั้น |
