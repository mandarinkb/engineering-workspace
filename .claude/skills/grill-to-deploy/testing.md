# การพิสูจน์: Bruno และ Playwright

หลักเดียวที่ครอบทั้งสองอย่าง: การตรวจนับเป็นหลักฐานก็ต่อเมื่อมันมีโอกาสล้มได้ ก่อนเชื่อ ✓ ถามว่าถ้าระบบพัง ตัวตรวจนี้จะล้มไหม

## Bruno (API แบบ black-box กับ stack จริง)

```bash
cd projects/bot-orchestration-platform/bruno
bru run --env minipc                       # ทั้งชุด (CLI: npm i -g @usebruno/cli@4.3.0)
RESTART_CMD="ssh -o BatchMode=yes minipc 'cd ~/Workspace/engineering-workspace && /usr/libexec/docker/cli-plugins/docker-compose -f docker-compose.yml -f ../bop-lan.override.yml up -d --force-recreate --no-deps bop-api'" ./run-with-restart.sh minipc
```

- ชุดนี้ใช้เวลานาน รันเบื้องหลังแล้วอ่านไฟล์ผลทั้งไฟล์ ดึงรายการที่ล้มด้วย `bru run --reporter-json <ไฟล์>` แล้วอ่านฟิลด์ `error` และ `testResults` ของแต่ละ request
- `seq` ต้องไม่ซ้ำในโฟลเดอร์ ตรวจหลัง merge ทุกครั้ง (หลาย ticket มักต่อท้ายด้วยเลขเดียวกัน): `for d in */; do grep -h "^  seq:" $d*.bru | sort | uniq -d | sed "s#^#DUP in $d: #"; done` และจัดลำดับให้ request ที่อ่านผลของงาน async อยู่หลัง request ที่รอให้งานนั้นจบ
- **cookie jar:** Bruno CLI เก็บ cookie จาก login แล้วแนบให้ทุก request แม้ request ตั้ง header `Cookie` เองหรือเว้นว่าง request ที่ต้อง "ไม่มี session" จึงต้องอยู่หลัง request logout (server สั่งลบ cookie แล้ว jar ทิ้ง) หรือรันด้วย `--disable-cookies`
- Bruno CLI อ่าน SSE ที่เปิดค้างไม่ได้ ตรวจ stream ด้วย `curl -N --max-time 3`
- test ตรึงพฤติกรรมจริงของ API ตอนนี้ ถ้าพฤติกรรมที่ตรึงน่าแปลก (เช่น config ไม่ครบแล้วได้ 202) เขียนคอมเมนต์บอกว่าจงใจตรึง
- `run-with-restart.sh`: ชุดหลัก → สร้าง Job ที่ค้างนาน (ชี้ไปที่อยู่ที่ไม่ตอบ) และ **poll จนเป็น `running` จริง** ก่อน recreate `bop-api` → recreate → รัน `after-restart` → ตรวจ stream ของ log จากก่อน restart → ตรวจว่า Job ที่ค้างกลายเป็น `failed` ถ้า Job ไม่เคยเป็น `running` สคริปต์ต้องขึ้น SKIPPED และถ้าถูกยกเลิกแทนที่จะถูกกวาดต้องขึ้น NOT PROVEN ห้ามผ่านเงียบ
- ก่อนใช้ที่อยู่ที่ค้าง ตรวจจากเครื่องปลายทางว่ามันค้างจริง (`curl -m 5` ต้องจบด้วย exit 28 ไม่ใช่ล้มทันที)

## Playwright

**เลือกเครื่องมือ:** ค้นด้วย `ToolSearch` คำว่า `playwright` ก่อนทุกครั้ง ถ้าเจอ tool ของ Playwright MCP ให้ใช้มัน (ติดตั้งด้วย `claude mcp add playwright -s user -- npx -y @playwright/mcp@0.0.86` tool จะโหลดใน session ที่ **เริ่มหลัง** ติดตั้งเท่านั้น และชื่อ tool ให้อ่านจากผลค้นหา ไม่เดา) ถ้าไม่เจอ ให้บอกผู้ใช้ตรงๆ ว่าไม่ได้ใช้ MCP แล้วใช้ไลบรารีตัวเดียวกัน ผลเทียบเท่า

**ไลบรารี:** ติดตั้งใน scratchpad (`npm i playwright@1.56.1`) ขับ Chrome ที่ติดตั้งในเครื่อง `chromium.launch({ channel: "chrome", headless: false, slowMo: 450 })` เมื่อผู้ใช้อยากเห็นบนจอ ไม่งั้นใช้ headless

**รูปแบบสคริปต์:**
- ห่อแต่ละขั้นด้วยตัวที่ดัก error: พิมพ์ ✓/✗ พร้อมสิ่งที่เห็นจริง ถ่ายภาพเมื่อ ✗ แล้วไปต่อ เพื่อเห็นผลทุกขั้นในรอบเดียว
- รันเบื้องหลังแล้วอ่านไฟล์ผลทั้งไฟล์
- เขียน ID ของข้อมูลที่สร้างลงไฟล์ state เพื่อลบตรงตัวทีหลัง
- ก่อนเขียน selector อ่านคอมโพเนนต์ (`aria-label`, ข้อความบนปุ่ม, `id`) ไม่เดา

**กันผ่านปลอม:**
- ตรวจการเปลี่ยนสถานะ (เช่น running → failed) ต้องรอเห็นสถานะเริ่มต้นก่อน งานที่จบใน 2 วินาทีไม่ใช่หลักฐาน ใช้งานที่ค้างนาน (ที่อยู่ที่ไม่ตอบ ลองครั้งเดียว) เพื่อให้มีช่วงที่เห็น
- พิสูจน์ว่า "ไม่ได้ reload" ด้วยการฝังตัวแปรในหน้า (`window.__marker = ...`) แล้วตรวจว่ายังอยู่หลังสถานะเปลี่ยน
- คำเตือนที่สคริปต์เขียนเองแปลว่ายังไม่พิสูจน์ แม้บรรทัดจะขึ้น ✓
- การตรวจที่อ่านข้อความต้องอ่านให้ยาวพอ ถ้าตัดสั้นจะไม่เจอคำที่ใช้ตรวจแล้วขึ้น ✗ ปลอม
- เมื่อ ✗ ให้รันซ้ำด้วยตัวเลือกที่แก้แล้วก่อนสรุป ว่าเป็นความผิดของสคริปต์หรือของระบบ ห้ามสรุปจากการเดา

**ทัวร์ UI ของคนอื่น (เช่น Temporal UI):** อ่านอย่างเดียว เปิดหน้า เมนู กล่อง แล้วปิด ไม่กดปุ่มที่เปลี่ยนข้อมูล (Terminate, Delete, Reset, Pause, Start, บันทึกฟอร์ม) ในเอกสารที่เขียนจากการทัวร์ แยกให้ชัดว่าสิ่งไหนเห็นจริง สิ่งไหนมาจากความรู้ทั่วไป

**ที่ติดซ้ำ:** `hasText` แบบ regex `^...$` หาลิงก์ที่มีไอคอนปนไม่เจอ ใช้ `getByRole("link", { name, exact: true })` หรือ `href` · checkbox ในตารางที่รีเฟรชเองอาจถูกวาดใหม่ระหว่างคลิก ใช้ `click({ force: true })` แล้วตรวจผลจากข้อความที่ตามมา
