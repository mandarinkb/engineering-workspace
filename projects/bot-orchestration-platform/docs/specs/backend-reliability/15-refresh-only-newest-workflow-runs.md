# 15: รีเฟรชอัตโนมัติของหน้า Workflow Runs ไม่ควรโตตามจำนวนหน้าที่โหลดไว้

Spec: [backend-reliability.md](../backend-reliability.md)

**ที่มา (ผล code review ของ ticket 01-12):** หน้า Workflow Runs ใช้ `useInfiniteQuery` ร่วมกับ `refetchInterval` ทุก 10 วินาที TanStack Query จะดึง "ทุกหน้าที่โหลดไว้" ใหม่ทีละหน้าต่อกัน (token ของหน้าถัดไปมาจากหน้าก่อนหน้า) ผู้ใช้กด "โหลดเพิ่ม" 20 ครั้ง จะเกิด 20 คำขอต่อรอบ และแต่ละคำขอเรียก ListWorkflow ของ Temporal ภาระของ `bop-api` และ Temporal โตตามที่ผู้ใช้เลื่อนไป

**Status:** deferred — ตัดสินใจร่วมกับผู้ใช้ให้เลื่อนไปก่อน เพราะต้องกดโหลดเพิ่มหลายสิบครั้งจึงจะรู้สึก และทางแก้ที่ง่ายที่สุด (หยุดรีเฟรชเมื่อโหลดเกินหน้าแรก) ขัดกับเรื่องราวที่ 48 ใน spec ("รีเฟรชต้องไม่ทำให้แถวที่โหลดไว้แล้วหาย")

**กลับมาทำเมื่อ:** มีคนใช้หน้านี้จริงจนเห็นว่าช้าหรือเห็นภาระเพิ่มบน Temporal หรือเริ่มมี Schedule ที่สร้าง run ถี่มากกว่านาทีละครั้ง

**ทางเลือกที่ประเมินไว้แล้ว:**
- รีเฟรชแค่หน้าแรกแล้วต่อหัวรายการให้ (ถูกต้องที่สุด แต่ต้องจัดการรวมข้อมูลเอง)
- จำกัดจำนวนหน้าที่เก็บด้วย `maxPages` (ตัดหน้าเก่าทิ้ง ผู้ใช้ต้องกดโหลดเพิ่มใหม่)
- หยุดรีเฟรชเมื่อโหลดเกินหน้าแรก (ง่ายสุด แต่ข้อมูลที่ผู้ใช้เห็นเก่าลงเรื่อยๆ)
